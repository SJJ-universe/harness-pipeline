## End-to-end loop verification

Operator picks "보안" preset →
  ↓ dropdown change handler →
  ↓ `selectedPresetId="security"` (component state) →
  ↓ click "→ Codex 비평 요청" button →
  ↓ `client.sendToCodex(sid, {instruction, preset:"security", store})` →
  ↓ POST `/api/review-sessions/<id>/send-codex` body `{instruction, preset:"security"}` →
  ↓ routes `_resolvePresetId("security")` → `"security"` →
  ↓ `manager.sendCodex` (state → AWAITING_CRITIQUE) →
  ↓ `dispatcher.dispatchCodex({presetId:"security"})` →
  ↓ `_buildCodexPrompt`: prepends `[Preset: Security]\n<security codex prompt>\n──────────────\n` + replaces default severity boilerplate with security preset's severity instruction →
  ↓ audit chain `review_session_dispatch_started {data.presetId:"security"}` →
  ↓ `codex.exec(prompt, {reviewSessionId})` →
  ↓ Codex critique arrives in security-focused frame →
  ↓ stdout chunks → `manager.recordCodexChunk` → broadcast `codex_stream_chunk` →
  ↓ critique completion → `manager.recordCritiqueReceived` + audit `review_session_dispatch_completed {data.presetId:"security"}`

Verified end-to-end via integration test `S3-c routes: presetId reaches audit chain via dispatcher` (review-session-routes-preset.test.js:368).

## Decisions worth re-reading later

1. **`hidden` attribute over `style.display`**: First UI cut used `wrap.style.display = "none"` for the `no-client` case. The existing action-row test stub doesn't include `.style`, so legacy tests broke. Switched to standard HTML `hidden` attribute — equivalent to display:none, a11y-aware, browser/stub-portable, CSS respects `[hidden]` without an extra rule.

2. **Preset validation BEFORE state transition**: A typo'd presetId on `send-codex` previously would have advanced the manager to `AWAITING_CRITIQUE` and then 400'd. Operator would have to archive + recreate. Now `_resolvePresetId` runs first; invalid → 400 with state untouched, runner not invoked, audit clean. Pinned by integration test `S3-c routes: send-codex with unknown preset → 400 invalid_preset BEFORE state transition`.

3. **Dispatcher defense-in-depth on presetId**: Routes layer is the primary validator with the prettier error message. The dispatcher ALSO rejects unknown presetId with `DISPATCH_INVALID_INPUT`. This catches future scripted callers (CLI tools, integration tests) that bypass routes.

4. **System-prompt bodies never leak to browser**: `GET /api/review-presets` returns `listPresetSummaries()` (id+label+description only). Full `codexSystemPrompt` / `claudeSystemPrompt` lives server-side and reaches the LLM via the dispatcher. The browser never sees the prompt text — keeps the surface minimal and avoids "operator copied the system prompt and tried to bypass" attacks.

5. **`Promise.resolve().then(...)` for fetch deferral on mount**: Calling `client.listPresets()` synchronously inside `create()` would mean dropping a Promise into the constructor and firing during render. Defer via microtask — `create()` returns sync, fetch arrives next microtask, render() re-fires when state lands. Tests handle by `await flushPromises()`.

6. **Soft-fail on listPresets failure**: If the GET 5xxs / network drops, the dropdown shows `(preset 목록 불러오지 못함…)` disabled stub but action buttons remain enabled. Operator continues with free-form prompts — same surface as before SMART-3. Avoids cascading failure.

7. **Preset opts auto-omit when null**: Client and panel both treat `preset: null` / `preset: ""` / `preset: 42` as "no preset" — body field stays unset rather than being `null`. Server's `_resolvePresetId(undefined)` returns null; same as before. Avoids `JSON.stringify({preset: null})` ambiguity at the wire.

8. **Severity tag preservation**: All 6 presets define their own severity-tag instruction (the tags `[critical]/[high]/[medium]/[low]` always exist; what each MEANS in the domain differs). Dispatcher's `_severityCountsFromFindings` parser keeps working because every preset enumerates all 4 tags.
