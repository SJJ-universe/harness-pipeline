## 8 decisions worth re-reading

1. **§1 Verdict has THREE tiers, not two** — `PASS` /
   `PASS-WITH-CONCERNS` / `FAIL`. The middle tier exists because
   "no FAIL but one DOUBT" is genuinely ambiguous in real review
   cycles. Forcing reviewers into binary PASS/FAIL would either
   inflate PASS (hiding real concerns) or inflate FAIL (alarming
   committers about minor doubts). Three tiers map directly to the
   reviewer's mental model.
2. **Cap-movement recommendations are decoupled from verdict** —
   `MOVE` / `DEFER` / `BLOCK` is a separate axis from
   `PASS/PASS-WITH-CONCERNS/FAIL`. Real combinations exist:
   - `PASS + DEFER` = "regression-free but evidence is incomplete"
   - `PASS-WITH-CONCERNS + DEFER` = "advance work BUT not the cap
     yet"
   - `PASS + MOVE` = the cap-movement-day combination
   - `FAIL + BLOCK` = the most-bad combination
3. **Required vs optional sections marked with HTML comments** —
   `<!-- REQUIRED -->` / `<!-- OPTIONAL -->` after the section
   heading is machine-readable (the structure tests verify the
   markers) AND human-readable (reviewer can scan headers to see
   what's mandatory). The alternative (separate REQUIRED.md
   document) splits the contract.
4. **§3 categories MIRROR EXR-b matrix exactly** — not "similar to,"
   not "subset of." If the matrix has 8 categories with specific
   names, the summary has 8 §3 subsections with those exact names.
   Tests pin this down so a future EXR-b category rename without
   updating EXR-d would fail loudly.
5. **Appendix's "DON'T invent new cap definitions"** — without this
   guard rail, an enthusiastic reviewer could invent "Compliance
   readiness +1" or similar caps that the scorecard rubric doesn't
   actually have. The 3-row appendix table is the canonical list;
   the imperative tells reviewers where to stop.
6. **§0 reminds reviewer to RECOMPUTE bundle sha256** — rather
   than trusting `bundle.sha256` in the JSON. The bundle
   self-reports its own hashes; a tampered bundle could lie.
   Reviewer recomputes from the raw bytes; matches → trust the
   bundle's other claims; mismatch → critical finding.
7. **§4 PASS fallback is explicit** — "No findings. All sampled
   rows verified." If a reviewer with no findings just leaves §4
   blank, future readers can't tell if the reviewer skipped the
   section or genuinely had no findings. The fallback statement
   forces a positive declaration.
8. **§8 privacy is a checklist (`- [ ]`), not prose** — markdown
   checkboxes force the reviewer to actively confirm each privacy
   claim. Prose paragraphs are easier to skim past. The checklist
   is mechanically scannable AND legally clearer.

## What's deferred / out of scope

Foundation is shipped; these are follow-up slices:

- **Real reviewer engagement** — finding an external reviewer,
  scheduling, getting them set up. Operator-time / reviewer-time.
- **Multi-summary aggregation** — a tool that reads all
  `*-external-review-summary.md` files and aggregates verdicts
  across cycles for trend reporting. Today the §5 comparison is
  hand-filled.
- **Summary signing** — GOV-AUDIT-0-style HMAC sealing of the
  summary so the cap-movement gate can verify "this summary was
  written by the named reviewer, not tampered post-commit."
  Today the summary is committed plain markdown.
- **i18n of the template** — currently English-only. Korean
  reviewers fill it in English (or in Korean prose with English
  field names). Future round could add a ko version.
- **Finding ledger** — a separate file that aggregates F.N
  finding records across summaries so committers can see "F.3
  was opened in cycle 1, F.3 was closed in cycle 3." Today
  reviewers re-state findings in §5 comparison.
- **Auto-populate §0 from bundle** — a script that reads a
  bundle JSON and pre-fills the §0 header (review id / bundle
  path / bundle sha256 / verdict). Saves reviewer typing but
  loses the "recompute sha256" canary unless carefully
  designed.
- **Live-link the matrix row references** — when a reviewer
  marks a finding against matrix row 5.2, today they cite the
  row number in §4. A future round could embed the matrix row's
  test/code/audit-verb directly into the finding template so the
  reviewer doesn't have to re-look-up.
