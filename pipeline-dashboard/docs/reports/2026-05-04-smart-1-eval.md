**7 frozen rules**:

| # | ID | Severity | Trigger |
|---|---|:---:|---|
| 1 | `complete-profile-setup` | critical | !hasActiveProfile |
| 2 | `resolve-pending-approvals` | high | approvalPending |
| 3 | `request-codex-review` | medium | codexReviewMissing |
| 4 | `monitor-active-runs` | info | counts.activeRuns > 0 |
| 5 | `export-audit-evidence` | info | auditExportReady && !needsHumanDecision |
| 6 | `public-sector-pii-block` | critical | publicSector && hasPii |
| 7 | `public-sector-evidence-trail` | high | publicSector && auditExportReady |

Each rule has: id / severity / titleKey + titleFallback / bodyKey + bodyFallback / ctaKey + ctaFallback / ctaActionId / appliesTo(ctx) / meta(ctx).

`recommendFromContext(ctx, {dismissedIds})` returns sorted Array<rec> ordered by SEVERITY_ORDER (critical → high → medium → info) then by rule index for ties.

null ctx → empty list (graceful degrade — conservative "we don't know" stance).

## 5. Known limitations + follow-ups

### 5.1 SMART-1 round itself
- Dismiss state is in-memory only — page refresh resets dismissed list. Future SMART round (or this one's polish) can persist via localStorage keyed on rule ID.
- 7 rules is a pragmatic minimum. Future rounds may extend (e.g., remoteRunnerActive when remote mode enabled, evidenceLedger growth alerts, etc.). Each addition is a frozen-list change with PR review.
- CTA dispatch fallback for SMART-1-specific actions (`open-review-sessions` / `open-recent-results` / etc.) currently routes to `onOpenSettings` as safe destination. Future SMART rounds can refine each to its proper destination.
- Engine output isn't cached between snapshots — fully recomputes every store publish. Fine for typical case (≤4 recs); could memoize if performance becomes an issue.

### 5.2 Out-of-scope (later SMART rounds)
- **SMART-2** Policy-backed Hard Gates — uses booleans + posture to enforce deny on dispatch (Safety cap candidate).
- **SMART-3** Expert Review Presets — uses context flags to pre-fill review prompts.
- **SMART-4** Redacted Run Memory — sources decisionContext at decision time for "what was happening when this approval fired".
- **SMART-5** Institutional Policy Packs — pluggable rules consume same adapter outputs (Public-sector readiness cap candidate).
- **SKILL-PACK-0** — distributable expertise consuming decisionContext for skill activation.
