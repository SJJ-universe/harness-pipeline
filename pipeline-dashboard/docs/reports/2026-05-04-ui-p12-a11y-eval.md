## 1. What landed

### 1.1 P12-a — A11y rule catalog (commit `166c218`)

| File | Role |
|---|---|
| `package.json` + `package-lock.json` | `axe-core` ^4.11.4 devDep (1 package added; 0 vulnerabilities) |
| `scripts/visual-live/a11y-rules.js` | Frozen exports: A11Y_AXE_TAGS / A11Y_AXE_DISABLED_RULES_ALL / A11Y_AXE_DISABLED_RULES_LEGACY / A11Y_FAILING_IMPACTS / A11Y_CUSTOM_RULES + summarizeCellA11y aggregator |
| `tests/unit/visual-live.a11y-rules.test.js` | 24 stub-page tests |

axe ruleset: WCAG 2.0/2.1 Level A + AA (~50 rules). Disabled by default:
- All routes: `color-contrast` (design tokens evolving in UI-P arc)
- Legacy route only: `region`, `landmark-one-main`, `landmark-unique`

Failing impact policy: only `critical` + `serious` axe violations fail the cell. Moderate/minor logged as warnings.

2 harness-specific custom rules:
- `lang-matches-locale` — `<html lang>` reflects active i18n locale (HarnessI18n.getLang → data-locale attr → html.lang fallback). Critical for KO/EN screen reader pronunciation.
- `skip-link-focus-visible` — first-Tab focuses `.skip-link` AND its visual state changes (4-axis: position / opacity / transform / size).

### 1.2 P12-b — A11y runner (commit `8be0236`)

| File | Role |
|---|---|
| `scripts/visual-live/a11y-runner.js` | `runA11yMatrix({base, ...})` orchestrator + helpers (runCustomRules, buildAxeDisabledRules, buildAxeRunConfig, buildA11yManifest) |
| `tests/unit/visual-live.a11y-runner.test.js` | 17 stub-injection tests |

Per-cell flow:
1. Navigate (waitUntil domcontentloaded → waitForSelector → 250ms post-paint delay)
2. Inject axe-core via `page.addScriptTag({content: axeCore.source})`
3. Run `axe.run(document, cfg)` inside page.evaluate
4. Run 2 custom rules
5. Aggregate via summarizeCellA11y

Manifest schema `harness-visual-a11y/v1` (distinct from capture's `v1` and assert's `v1` — future round can fuse safely).

Per-cell fault model matches capture/assert: navigation timeout / selector miss / axe injection failure → `{failed: true, failureReason}` recorded, loop continues. Single-cell failure NEVER aborts matrix.

## 5. Known limitations + follow-ups

### 5.1 UI-P12 round itself
- `color-contrast` axe rule disabled by default until UI polish round stabilizes design tokens
- 2 custom rules — pragmatic minimum. Future custom rules:
  - keyboard-trap detection (modal focus traps)
  - locale-toggle-updates-html-lang (currently checked statically; could be tested by interacting)
  - reduced-motion compliance verification
- axe-core runs against the FIRST-PAINT static state. Doesn't catch a11y regressions introduced by dynamic state (e.g., modal opening, run state changes). Follow-up round candidate: state-driven a11y matrix.
- No baseline-style comparison. Manifests are independent point-in-time snapshots. Operator/CI compares manually.

### 5.2 Out-of-scope (later rounds)
- UI-P13 Dead Button — click-and-verify on the same harness; could fuse with a11y to ensure clicks don't break a11y state
- UI-Doc-Gov — visual contract governance for all 3 manifest types (capture/assert/a11y)

- Color contrast under stable design tokens — separate UI polish round
- Korean WA-ARIA conformance certification — operator workflow round

## 7. Reproduction

```bash
cd pipeline-dashboard

# One-time setup (shared with UI-P10/P11)
npm run visual:install-browsers

# Standard a11y verification (16 cells × axe + 2 custom)
npm run visual:a11y-live

# With label
node scripts/visual-a11y-live.js --label "public-sector-audit-2026-05-04"

# Disable noisy axe rules during investigation
node scripts/visual-a11y-live.js --disable-rule region --disable-rule duplicate-id

# CI manual dispatch
# GitHub UI → Actions → "UI-P12 Live Browser A11y Verification" → Run workflow
```

Verify exit semantics:
```bash
npm run visual:a11y-live; echo "exit: $?"
# 0  → all 16 cells ok (no critical/serious axe + 0 custom failures)
# 1  → at least one cell failed (manifest still written)
# 2  → CONFIG (browsers missing, port collision, server boot fail)
```
