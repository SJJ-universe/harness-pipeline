POL-UI-1 closes the POL-c deferred UI but does not move the cap. Per
the established cap-movement deferral pattern (POL / FP / EXR all
maintained 120/126 with deferred cap movement on operator-time
evidence):

- POL-c plumbed the data; POL-UI-1-a renders it. This is **regression

  **Public-sector readiness** — the rubric line that watches for

  1. Operator runs `harness-start.bat` with
     `HARNESS_DEPLOYMENT_PROFILE=public-sector` for ≥1 working week
  2. The pack-info-card has been **visible** in the simple-shell

  5. EXTERNAL-REVIEW-0 reviewer walks the pack-info-card row in the
     claim/evidence matrix (Cat 6, row 6.5 + 6.6) and marks PASS

The matrix's Cat 6 already has a row 6.6 for `GET /api/policy-packs`

## 8 decisions worth re-reading

1. **Card placement = banner above the 4-card grid, not a 5th cell** —
   the operator-workflow trio (지금 AI가 하는 일 / 승인 필요 / 최근
   결과) is task-oriented; the pack-info card is *posture-oriented*.
   Mixing them in the grid would crowd the workflow cards. The banner
   placement signals "this is context, not work".
2. **Read-only, no mutations** — the panel never calls
   `store.setPolicyPacks` or any other mutator. POL-c has the legacy-
   bridge fetching once at boot; the panel is purely a renderer. This
   matches the legacy-bridge "packs frozen at boot" decision (pack
   change requires server restart, so polling is wasted work).
3. **Collapsible alternatives, not always-expanded** — operators look
   at this card 95% of the time to confirm "current pack is X". The
   5% case is "what would change if I switched packs". Collapsing the
   alternatives by default reduces cognitive load on the common case
   without hiding the comparison feature.
4. **Truncate descriptions at 140 chars in alternatives** —
   defensive against a future pack with a verbose description string.
   The truncation uses `.slice(0, 137) + "…"` (3 chars for ellipsis
   so total is 140). Operator can read full description by visiting
   the route directly.
5. **Empty placeholder, not skeleton screen** — the pack-info data
   arrives within ~50ms of mount (legacy-bridge boot fetch). A
   skeleton screen would flash for less time than the eye perceives;
   a simple "불러오는 중..." text is cheaper and clearer.
6. **`data-public-sector="true"` attribute on the badge, not a class** —
   this is for future CSS variant styling. Attribute-based selectors
   (`[data-public-sector="true"]`) compose better with multi-state
   styling than class toggles.
7. **`onCta` seam exists today but no-ops** — future slices may add
   "compare packs side-by-side" or "open deployment guide" buttons.
   Reserving the seam now means future slices don't break the panel
   constructor signature. Tests pass `_meta` ignored stubs to verify
   the seam is callable without throwing.
8. **Mount-position invariant is a structural test, not a CSS test** —
   the test asserts that `.ss-pack-info-mount` lives BETWEEN
   `.ss-recs-mount` and `.ss-grid` in `root.children` order. CSS
   styling is operator-perceivable but doesn't affect functional
   contract. The structural test catches refactors that accidentally
   reorder the mount slots; CSS regressions are caught by visual
   contract tests + manual screenshot review.

## What's deferred / out of scope

Foundation is shipped; these are follow-up slices:

- **CSS styling** — the panel renders functional but with default
  browser styling (no color, no border). Visual polish (border
  radius, posture color tones, public-sector amber badge) is a CSS
  follow-up. Same pattern as recommendations-card and next-action-
  card which also defer dedicated styling.
- **Pack rule details** — the 9 rule fields (allowLocalExecutor,
  allowPlaintextSecrets, etc.) are visible in the alternatives card
  badges (3 most-relevant) but the full table is not surfaced. A
  future "expand details" toggle could show the full 9-row table.
- **Pack comparison side-by-side** — clicking an alternative card
  could open a 2-column compare view (current vs alternative). The
  `onCta` seam is reserved for this.
- **Deployment guide link** — pack-info-card could include a link to
  `docs/harness-pipeline-distribution-guide.md` for operators new to
  pack selection. Today the operator must find that doc separately.
- **Reactive pack switch** — pack changes still require server
  restart (HARNESS_DEPLOYMENT_PROFILE env + reboot). A future POL-e
  could add a "switch pack" UI flow with confirmation modal +
  graceful runner shutdown.
- **Per-pack policy preview** — selecting an alternative could
  preview "if you switched, here's what would change in the gate
  matrix and audit verbs". Useful for operators evaluating a posture
  change.
- **i18n smoke for the 10 new keys** — the existing i18n parity
  invariant (ko/en key sets equal) catches deletions; a future test
  could add per-key smoke ("pack catalog visible in both locales").
- **Visual regression integration** — the visual contract baseline
  was refreshed but a Playwright/Puppeteer screenshot diff against
  the simple-shell render is not yet wired. UI-P9 visual.contract
  test catches script-tag drift, not rendered-pixel drift.
