## End-to-end loop verification

**Production fail-closed**:

1. Operator sets `ORCHESTRATOR_DEPLOYMENT_PROFILE="publicsector"` (typo)
2. server.js boots → `resolveDeploymentProfile()` throws `POLICY_PACK_UNKNOWN`
3. server.js catch fires:
   ```
   [harness] FATAL: Unknown ORCHESTRATOR_DEPLOYMENT_PROFILE="publicsector".
   Recognized: developer-lab, finance-high-privacy, offline-internal-network,
   public-sector, standard. Set ORCHESTRATOR_POLICY_FAIL_OPEN=1 to fall back...
   ```
4. `process.exit(1)` — pipeline NEVER runs under unintended posture
5. Operator sees error in launcher logs / docker logs / systemd journal

**Dev escape**:

1. Operator sets `ORCHESTRATOR_DEPLOYMENT_PROFILE="publicsector"` + `ORCHESTRATOR_POLICY_FAIL_OPEN=1`
2. resolveDeploymentProfile returns standard profile + `resolvedFromFallback=true` + `unknownRequested="publicsector"`
3. server.js boots normally
4. evidenceLedger receives `deployment_profile_resolved` row with the dev-escape signal — operator dashboard or forensic auditor sees it later

**Successful boot under each pack**:

1. Operator sets one of 5 recognized pack ids
2. resolveDeploymentProfile returns frozen profile populated from the pack rules
3. server.js boots normally
4. evidenceLedger receives one `deployment_profile_resolved` row
5. Subsequent SMART-2 hard gate decisions / SMART-4 run memory writes / GOV-* runner enforcement all consult the same profile

Verified end-to-end via:
- `S5-c: typo'd ORCHESTRATOR_DEPLOYMENT_PROFILE='publicsector' → exit 1 + FATAL stderr` (smoke)
- `S5-c: typo + ORCHESTRATOR_POLICY_FAIL_OPEN=1 → boots as standard (legacy escape)` (smoke)
- `S5-c boot audit: dev escape lands resolvedFromFallback:true + unknownRequested` (integration)

## Decisions worth re-reading later

1. **Production fail-closed reverses pre-SMART-5 silent-fallback**: The single most behavior-changing piece. Pre-SMART-5 typo'd env → silent standard. Post-SMART-5 typo'd env → process.exit(1) at boot. Operators who mean "public-sector" but type "publicsector" now see the error before pipelines run. Rationale: the failure mode public-sector deployments cannot tolerate is a SILENT posture downgrade.

2. **ORCHESTRATOR_POLICY_FAIL_OPEN=1 is the escape hatch**: Dev environments + migration windows where operators are intentionally typo-tolerant can set this env. The fallback is logged in the audit chain (resolvedFromFallback=true + unknownRequested=`<typo>`) so a forensic review still sees what happened.

3. **Empty/unset env is NOT a typo**: When ORCHESTRATOR_DEPLOYMENT_PROFILE is unset, resolver returns standard with `resolvedFromFallback=false`. This is backward-compatible with every pre-SMART-5 deployment that just doesn't set the env. Only an EXPLICIT-unknown value triggers fail-closed.

4. **Cross-field invariants validated at module load**: An author who adds a public-sector pack but forgets `allowLocalExecutor=false` → registry throws at `require()` time, not at first `resolveDeploymentProfile`. Catches mistakes during code review / unit-test load, not during operator deployment.

5. **Plaintext rule generalized to pack + env-opt-in**: pack.allowPlaintextSecrets gates whether ORCHESTRATOR_ALLOW_PLAINTEXT_SECRETS=1 even matters. Public-sector packs have allowPlaintextSecrets=false in the rule (cross-field invariant) so the env opt-in is ignored under public-sector posture — defense-in-depth preserved.

6. **`hardGatesDefault` is per-pack, NOT auto-implied by publicSector**: SMART-2's ORCHESTRATOR_HARD_GATES env can be opted-in independently. The only pack with hardGatesDefault=true is finance-high-privacy (the strictest). Operators of public-sector posture choose graduated rollout (warn → hard).

7. **Boot audit emit AFTER evidenceLedger construction**: Order matters. The fail-closed catch fires BEFORE evidenceLedger exists (no audit row possible). The success-path emit comes AFTER evidenceLedger is created. Ledger I/O failure on emit is defensively swallowed — boot continues without the row.

8. **`deployment_profile_resolved` lands under "system" runId**: Same convention as policy_gate_blocked / runner_handshake / runner_host_lost. Operators grep "system" runId for boot-time events; per-run runId for runtime events.

9. **Smoke vs integration test split**: Process.exit(1) is process-level → can't observe in-process. Smoke test spawns child node process to verify exit code end-to-end. Audit-row contract is in-process → integration test mimics server.js emit pattern to lock the verb shape without needing full server boot.

10. **Backward compat preserved across the resolver rewrite**: Every existing test using "standard" or "public-sector" env values passes unchanged. The only test changed is the typo-fallback test (now tests fail-closed). All other behavior preserved — no breaking change for any existing deployment.

## What's deferred / out of scope

- **Per-pack live deployment evidence**: Plan §S §S-SMART-5 acceptance gate ("operator runs finance-high-privacy mode in production with no regressions for 1+ week") — scope for a future LV round.
- **UI pack selector**: An operator-facing UI to pick a pack from a dropdown (vs. setting env var) is out of scope. The existing setup wizard could be extended.
- **Pack export / import**: Pack rules are frozen in code. A pack-as-config-file feature (operators define their own packs in YAML/JSON) is a future consideration but introduces config-trust + auditing complexity.
- **Per-pack default ORCHESTRATOR_HARD_GATES override env**: The `hardGatesDefault` field is a pack rule but doesn't currently auto-set the runtime gate mode. SMART-2's `resolveGateMode(env)` ignores the pack default. Future work: extend resolveGateMode to consult deploymentProfile.hardGatesDefault when env is unset.
- **Per-pack default ORCHESTRATOR_RUN_MEMORY_DISABLE**: Same as above — pack rule exists but env is the runtime source of truth. Future enhancement.
- **Cross-pack policy migration tooling**: When operators move from public-sector to finance-high-privacy, an automated diff + audit row of "posture changed" would help compliance review. Not in scope.
- **Pack catalog UI**: Listing all 5 packs with descriptions in the operator dashboard. Module-level `listPackSummaries()` already returns the right shape; UI binding is the missing piece.
